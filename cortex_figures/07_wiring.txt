그림 07 / 25 — 연결 저장·계산 — 두 입력군, 0 패딩 열, 결정론적 gather
범주: C 신경망 구조
이미지 파일: 07_wiring.png (2200 × 1026 픽셀, PNG)
대상 프로그램: cortex_local_learning_v1.py + cortex_local_learning_v2_v1_guided_routing.py (v2.0.0)
==============================================================================
[이 그림이 보여 주는 것]
왼쪽: 수신 뉴런 하나가 입력을 합치는 방식. 오른쪽: 연결을 메모리에 저장하고 GPU/CPU 에서 계산하는 방식.

[왼쪽 — 입력 결합]
- 수신 뉴런의 입력은 A 군과 B 군으로 나뉜다. 각 입력에 가중치 w 를 곱해 군별로 더한다 (ΣA, ΣB).
- 보통 뉴런(linear): u = ΣA + ΣB
- 역할 뉴런(min2): u = min(ΣA, ΣB) — 교차, 곡선, 직선 연속, IT 결합처럼 "두 조건이 모두 있어야" 하는 역할.
- 저장 형식은 CSR: a_ptr · a_src · a_w (A 군), b_ptr · b_src · b_w (B 군), op_min (min2 여부).

[오른쪽 위 — 0 패딩 열]
- 이전 층 출력 x (칸 0 … n_src−1) 뒤에 값이 0 인 칸 하나(주소 n_src)를 붙인다.
- 빈 연결 칸은 −1 대신 이 0 칸을 가리킨다. −1 을 쓰면 배열 끝(마지막 뉴런)을 잘못 읽을 수 있기 때문이다.
- 빈 칸을 곱하고 더해도 합이 바뀌지 않는다.

[오른쪽 아래 — ELL 버킷]
- 팬인(입력 수)이 비슷한 행끼리 묶어 같은 폭의 표로 저장한다. 표의 각 칸은 입력 주소다.
- 행 r₂ 처럼 입력이 적은 행의 남는 칸은 n_src (0 값 열) 로 채운다 (점선 화살표).
- 계산: gather(주소로 값 모으기) → × w → 행 합. 축약 순서가 고정되어 있고 atomic 누적(index_add)을 쓰지 않아
  같은 입력이면 같은 결과가 나온다(결정성).
- 한 번에 모으는 원소 수는 max_gather_elements = 2²⁵ 이하로 나눠 계산한다. GPU 메모리가 부족하면 이 조각을
  절반으로 줄여 같은 배치를 다시 계산한다 (그림 18).

[기타 규칙]
- 같은 (수신 뉴런, 입력군, 송신 뉴런) 연결이 겹치면 가중치를 더해 하나로 합친다 (merge_sum, 개수 기록).
- CUDA 에서는 TF32 를 끄고 cuBLAS workspace 를 고정해 결정성을 요청한다.
- NumPy 경로와 PyTorch 경로는 같은 수식(gather·합·clamp·min·where)만 쓴다.

[관련 코드]
CSRBuilder, LayerSpec, Connectivity, BucketELL, LayerRuntime, Backend (take_cols, gather_cols, pad_zero_col),
DeviceManager

[그림 공통 색 규칙]
- 파란 실선 화살표: 순방향 감각 신호 (이미지 → LGN → V1 → V2 → V4 → IT)
- 분홍 점선 화살표: 교정 신호 (δ, L1 배달, q 갱신)
- 주황 선·칸: v2 에서 추가된 V1 안내 라우팅
- 파란 칸: 표본마다 새로 계산하는 값, 분홍 칸: 저장·학습되는 값 (q, prototype)
- 초록 칸: 통과·정상 종료, 빨간 칸: 제외·오류·금지
- 회색 화살표: 프로그램 부품 사이의 호출·기록 순서

그림 16 / 25 — 곡률 검사 결과 — 45° 허용보다 곡률 부호 검사가 훨씬 좁다
범주: E V1 안내 라우팅 (v2)
이미지 파일: 16_routing_curvature_result.png (2200 × 966 픽셀, PNG)
대상 프로그램: cortex_local_learning_v1.py + cortex_local_learning_v2_v1_guided_routing.py (v2.0.0)
==============================================================================
[이 그림이 보여 주는 것]
v2 구현에서 가장 중요한 결과다. spec 이 정한 Hermite 경로 정의에서는 곡률 부호 검사가 45° 현 방향 허용보다
훨씬 좁게 작동해, 새 두 모드에서 곡선 뉴런 대부분이 후보 없음(u = 0)이 된다.

[왼쪽 막대 — 곡률 부호 검사를 통과하는 현 방향 범위]
꺾임 κ 별로 φC 에서 몇 도까지 벗어난 현이 통과하는지 (Hermite 경로를 0.25° 간격으로 검사해 얻은 값):
  κ 15° → ±3.5°
  κ 30° → ±6.75°   (현재 설정, 주황)
  κ 45° → ±10.5°
  κ 60° → ±15.25°
빨간 점선 = 설정 허용 45°. 어떤 κ 에서도 통과 범위가 45° 보다 훨씬 좁다.
원인: 접선 길이를 |Q−P| 로 둔 Hermite 경로는 현이 두 접선 사이 중간 방향에서 조금만 벗어나도 S자로 휜다.

[오른쪽 막대 — 곡선 뉴런의 후보 상태 (학습 없이 구조만 만들어 셈)]
기본 설정 (128 px, V4 4×8, 곡선 뉴런 768)
  거리·방향 조건에서 후보 0: 271 (35.3 %)
  곡률 부호 검사로 모두 탈락: 337 (43.9 %)
  유효 후보 1개 이상: 160 (20.8 %)
  → 후보 없음 79.2 %
자체 검사 설정 (64 px, V4 3×12, 곡선 뉴런 864)
  302 (35.0 %) · 346 (40.0 %) · 216 (25.0 %) → 후보 없음 75.0 %
유효 후보 평균: 기본 0.46 개, 자체 검사 0.53 개. 후보가 있는 뉴런만 보면 약 2.2 개, 2.1 개.
경로 검사 탈락 건수: 기본 2,530 건, 자체 검사 2,607 건, 모두 곡률 부호 사유.

[의미]
- legacy → geometry_only 효과에는 곡선 뉴런 약 79 % 가 꺼지는 영향이 포함된다. legacy 는 이 뉴런들에도
  θA 방향 최근접 위치(없으면 같은 위치)를 줬다.
- 이것은 격자·기하 문제이며 V1 안내로 해결되지 않는다. 학습 실패와 구분해 기록한다.
- 기본 크기에서 원호 자극을 넣어 측정해 보니(R07) 세 모드의 선택 위치가 같았다. 후보가 적어 안내가 선택을
  바꿀 여지가 거의 없다는 뜻이다.

[데이터를 보고 완화하지 않았다]
바꾸려면 사용자가 판단해 설계 변경으로 기록한다 (메뉴 9-8 → design_changes.jsonl).
바꿀 수 있는 값: routing.max_chord_dev_deg, curvature_turn_tol_deg, dist_min_factor / dist_max_factor,
V4 격자 밀도(areas.V4.n_r / n_phi). 후보 부족을 숨기려고 뉴런 수·수용장·풀링을 동시에 바꾸지 않는다.

[기록 위치]
routing/routing_static_summary.json (후보 없음 비율·탈락 사유·고리별·방향별),
routing/missing_by_ring_orientation.csv (고리 · 편심도 · θA · 곡률 부호별)

[측정 방법]
작성 환경(NumPy)에서 CortexModel 로 V1·V2·V4 구조만 만들고 RoutingTable.static_summary 로 셌다.
통과 범위는 hermite_path · path_check 를 현 방향 −45° … +45° 에 0.25° 간격으로 적용해 구했다.

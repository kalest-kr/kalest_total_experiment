[이 그림이 보여 주는 것]
왼쪽: 후보 하나의 Hermite 경로 9 지점. 가운데: 그중 한 지점에서 V1 지도를 읽는 방법.
오른쪽: 점수 계산과 후보 선택 흐름.

[왼쪽 — 경로 지점]
t₀ = P 부터 t₈ = Q 까지 9 지점(M = 9). 실제 식으로 계산한 경로다 (κ = 30°).
동그라미 친 t₂ (t = 0.25) 지점을 가운데 칸에서 확대해 보여 준다.

[가운데 — 한 지점 읽기]
- 공간: 원영상 위치를 V1 의 로그-극좌표 사상 역좌표로 바꾼 뒤, 둘레 4 격자 위치의 쌍선형 가중치로 읽는다
  (반경은 log1p 축, 각도는 wrap). 지도 밖 지점은 무효다.
- 방향: V1 은 0°, 15°, …, 165° 12 방향 채널이다 (180° 주기). 이 지점의 경로 접선은 7.7° 라서
  0° 채널 0.49, 15° 채널 0.51 의 가중합으로 읽는다 (파란 굵은 선 두 개).
- a = Σ w · F1(위치, 접선 방향 두 채널)   ← 경로 방향의 반응
- b = Σ w · Σ(12 방향) F1(위치)          ← 같은 위치의 모든 방향 반응 합

[오른쪽 — 점수와 선택]
r_m = a_m / (b_m + ε), ε = 1e-6.  b_m < 0.001 이면 r_m = 0 (거의 0 인 신호에서 비율이 과장되지 않게)
S_k = (1/9) Σ_m r_m,  k = 1 … K (후보별)
S 는 [0, 1] 범위의 "방향 지지 정도" 다. 실제 곡선일 확률이나 정답 확률이 아니다.
최대 S > 0 ?
  예   → Q* = argmax S (같은 점수는 기하 순서 앞 칸)
  아니오 → Q* = 기하 첫 후보, no_guidance 로 기록 (V1 증거가 모두 0 이거나 유효 안내가 없음)
B = V4L4[Q*, θB] → u = min(A, B). S 를 u 에 곱하지 않는다. B = 0 이면 u = 0.
후보 0개 (빨간 칸) → missing_candidate, u = 0. 이것은 정적 후보 표에서 이미 정해지며 no_guidance 와 따로 센다.

[구현 방식]
모든 후보·지점의 공간 주소와 보간 가중치는 V4 를 만들 때 미리 계산해 둔다. 배치마다 gather · 곱·합 ·
마스크 argmax · min 만 하고, 매 배치 최근접 탐색이나 후보별 신경망 재실행을 하지 않는다.
표본 × 뉴런 × 후보 × 지점 중간 텐서는 조각으로 나눠 계산한다.
geometry_only 모드도 기록용으로 같은 S 를 계산하지만 선택에는 쓰지 않는다 (S_used_for_selection = False).

[기록하는 값]
- 선택 후보의 유효 지점 비율, r 최소·중앙값, 끝점 r 평균, 내부 r 평균
- S 가 높은데(≥ 0.5) 선택 입력 B = 0 인 사례 수 (high_S_but_zero_B). 앞단 풀링으로 사라진 정보를
  안내만으로 복원했다고 주장하지 않기 위한 기록이다
- missing_guide: 기하적으로 유효하지만 경로 위에 유효한 V1 지도 지점이 하나도 없는 후보 (S 는 늘 0)
- 추가 계산량: 표본당 약 곡선 수 × K × M × 12 원소 (기본 768 × 8 × 9 × 12)

[관련 코드]
GuideSampler.table, RoutingRuntime.scores / select, routing_rec_np, point_summary, routing_batch_stats,
routing_finalize, routing_reference_scores (float64 기준 구현, 검사용)
설정: routing.guide_epsilon 1e-6, guide_min_total 1e-3, high_guide_score 0.5

[그림 공통 색 규칙]
- 파란 실선 화살표: 순방향 감각 신호 (이미지 → LGN → V1 → V2 → V4 → IT)
- 분홍 점선 화살표: 교정 신호 (δ, L1 배달, q 갱신)
- 주황 선·칸: v2 에서 추가된 V1 안내 라우팅
- 파란 칸: 표본마다 새로 계산하는 값, 분홍 칸: 저장·학습되는 값 (q, prototype)
- 초록 칸: 통과·정상 종료, 빨간 칸: 제외·오류·금지
- 회색 화살표: 프로그램 부품 사이의 호출·기록 순서

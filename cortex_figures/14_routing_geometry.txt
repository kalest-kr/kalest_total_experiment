[이 그림이 보여 주는 것]
왼쪽: 첫 입력 위치 P 주변에서 둘째 입력 후보 Q 가 될 수 있는 영역과 실제 경로 예시.
오른쪽: 후보마다 거치는 경로 검사 순서.

[방향 정의]
- θA = 첫 입력 방향 (그림에서 0°), 곡률 부호 s = +1, 꺾임 κ = 30°
- θB = φB = θA + s·κ = 30° (둘째 입력 방향)
- φC = θA + s·κ/2 = 15° : P → Q 현이 향해야 하는 방향. 두 접선의 중간 방향을 연속 각도로 계산한다
  (0°/180° 이음매를 단순 평균하면 반대편을 고르게 되므로 그렇게 하지 않는다).
- 방향은 180° 주기 (선 방향)이고, 공간 진행 방향(앞/뒤)은 따로 관리한다.

[왼쪽 그림 읽는 법]
- 회색 부채꼴: 거리 [0.5D, 1.5D] 고리 안이면서 현 방향이 φC 에서 ±45° 이내인 영역 (기하 후보 조건)
- 점선 원호 D: 기존 국소 간격 (기대 거리)
- 주황 좁은 쐐기: 곡률 부호 검사까지 통과하는 영역, φC ± 6.75° (κ = 30° 일 때)
- 주황 굵은 선: φC 방향 Q 로 가는 경로. 한 방향으로 휘므로 통과
- 빨간 점선 두 개: 현이 φC 에서 30° 벗어난 후보. 위쪽은 S자로 곡률 부호가 바뀌고, 아래쪽은 처음부터 반대로 휜다.
  둘 다 3번 검사에서 탈락
- 세 경로는 spec 의 cubic Hermite 식으로 실제 계산해 그렸다 (|Q−P| = D):
  p(t) = (2t³−3t²+1)P + (t³−2t²+t)·vA + (−2t³+3t²)Q + (t³−t²)·vB,  vA = |Q−P|·tA, vB = |Q−P|·tB
  tA, tB = θA, θB 방향 단위 접선. p′(t) 는 이 기하 경로의 접선이며 학습 미분이 아니다.

[오른쪽 — 경로 검사 순서]
후보 Q: Q ≠ P, 거리 [0.5D, 1.5D], 현 방향 ±45° 를 먼저 만족해야 한다. 그다음 M = 9 지점 경로로 검사한다.
1 진행 방향: tA·(Q−P) > 0 이고 tB·(Q−P) > 0 (접선이 P → Q 진행과 반대면 탈락)
2 경로 접선 p′(t) 가 0 이 아님
3 곡률 부호: 이웃 경로 지점 사이 회전이 모두 s 쪽 (반대 회전 허용 0.5°)
4 접힘 없음: 총 |회전| ≤ 180°
5 경로 지점이 P 또는 Q 의 수용장 안
통과 → 기하 순서대로 K = 8 칸까지 채운다. 탈락은 처음 걸린 사유 하나로 기록한다 (rejected_reason).
(프로그램 내부 사유 코드: 1 curvature_sign, 2 folded, 3 zero_tangent, 4 outside_rf, 5 direction_conflict —
 그림의 번호는 검사 순서이고 사유 코드 번호와 다르다)

[정렬과 후보 없음]
기하 점수 = |d − D| / (0.5D) + 현 방향 오차 / 45°. 점수가 같으면 원래 입력 주소 순서.
유효 후보가 하나도 없으면 같은 위치로 대체하지 않고 missing_candidate 로 표시하며 u = 0 이다.
다른 역할 뉴런은 끄지 않는다. 후보 없음 비율은 영역·편심도·방향별로 기록한다.

[저장되는 후보 표]
주소, 좌표, 거리, 방향 오차, 경로 지점, 보간 가중치, 유효 마스크. 빈 칸은 −1 이 아니라 0 패딩 열을 가리킨다.

[관련 코드]
curve_directions, hermite_path, path_check, build_routing_table, RoutingTable, PATH_REASONS
설정: routing.dist_min_factor 0.5, dist_max_factor 1.5, max_chord_dev_deg 45, path_points 9,
      curvature_turn_tol_deg 0.5, max_candidates 8

[그림 공통 색 규칙]
- 파란 실선 화살표: 순방향 감각 신호 (이미지 → LGN → V1 → V2 → V4 → IT)
- 분홍 점선 화살표: 교정 신호 (δ, L1 배달, q 갱신)
- 주황 선·칸: v2 에서 추가된 V1 안내 라우팅
- 파란 칸: 표본마다 새로 계산하는 값, 분홍 칸: 저장·학습되는 값 (q, prototype)
- 초록 칸: 통과·정상 종료, 빨간 칸: 제외·오류·금지
- 회색 화살표: 프로그램 부품 사이의 호출·기록 순서

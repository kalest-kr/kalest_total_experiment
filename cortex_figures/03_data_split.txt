[이 그림이 보여 주는 것]
데이터 폴더를 읽어 학습·검증·시험 세트로 나누는 과정이다. 같은 사진의 변형이 서로 다른 세트에
흩어지지 않도록 그룹 단위로 나누는 것이 핵심이다.

[단계별 설명]
1. 데이터 폴더: 하위 폴더 이름 = 클래스 이름. 클래스 수는 자동으로 정한다.
2. 스캔: 지원 확장자 8종(.png .jpg .jpeg .bmp .gif .tif .tiff .webp)만 읽고, 실제로 디코딩해 본다.
   - 아래 빨간 칸으로 빠지는 것: 디코딩 실패(손상), 미지원 파일, 이미지가 없는 빈 클래스 폴더. 모두 기록한다.
3. 중복 그룹 묶기: 화소 내용이 같은 파일과, 이름 끝의 _aug · _copy · _dup · _flip · _rot(+숫자) · (1) 같은
   꼬리표를 뗀 이름이 같은 파일을 한 그룹으로 묶는다.
   - 같은 화소가 서로 다른 두 클래스에 있으면 라벨 충돌이므로 둘 다 제외한다 (오른쪽 빨간 칸).
4. 층화 그룹 분할: 클래스마다, 그룹 단위로, 고정 seed 로 섞어 나눈다. 한 그룹은 한 세트에만 들어간다.
   클래스마다 세 세트 모두에 표본이 들어갈 수 없으면 억지로 중복 배정하지 않고 오류(SplitError)를 낸다.
5. split_manifest.json: 항목 목록, 데이터 지문(SHA256), 분할 해시를 저장한다.

[아래 막대 읽는 법]
막대 길이는 기본 비율 train 70 % · dev 15 % · test 15 % 에 비례한다 (설정 data.split_ratios).
- train: q 교정, prototype 초기화와 에폭 끝 EMA 갱신에 쓴다.
- dev: 에폭마다 평가, 조기 종료(patience), 진단에 쓴다.
- test: 고정된 최종 모델의 평가에만 쓴다. 설정·에폭·모드 선택에 쓰지 않는다. 평가 횟수를 센다.

[기록]
data_report.json (손상·미지원·빈 클래스·중복 그룹·클래스 간 충돌·원본 크기), split_manifest.json,
class_to_index.json, evaluations.jsonl (모든 dev·test 평가 기록과 횟수)

[재개할 때]
파일 목록·지문이 분할 목록과 다르면 재개하지 않는다 (CompatibilityError).

[한계]
화소가 똑같은 중복과 이름 규칙만 그룹으로 묶는다. 다시 찍은 사진 같은 근접 중복은 탐지하지 않는다.

[관련 코드]
DatasetManager.scan, DatasetManager.split, DatasetManager.from_manifest, verify_files, Session.scan_and_split

[그림 공통 색 규칙]
- 파란 실선 화살표: 순방향 감각 신호 (이미지 → LGN → V1 → V2 → V4 → IT)
- 분홍 점선 화살표: 교정 신호 (δ, L1 배달, q 갱신)
- 주황 선·칸: v2 에서 추가된 V1 안내 라우팅
- 파란 칸: 표본마다 새로 계산하는 값, 분홍 칸: 저장·학습되는 값 (q, prototype)
- 초록 칸: 통과·정상 종료, 빨간 칸: 제외·오류·금지
- 회색 화살표: 프로그램 부품 사이의 호출·기록 순서
